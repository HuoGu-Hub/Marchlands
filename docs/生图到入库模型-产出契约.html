生图模型产出契约

Marchlands · 建筑资产 · 与现有 GLB 管线对齐

不要向模型要"一张好看的图"，也不要只要"一个随手导出的 GLB"。要它按合同交付四件套：正交设定表、规格单、自包含 GLB、同机位验收图。图负责表达形体，规格单负责让机器判得对错，GLB 负责能进运行时，验收图负责不开 Blender 也能比对。

四件产出物

产出作用判据
正交设定表告诉三维端"形"到底是什么，同时约束比例五视图同缩放同基线，无透视，顶视有完整屋顶轮廓
规格单 JSON把美术意图变成可校验字段，直接喂给 pack.json字段齐全，占地与高度以米为单位，面数与贴图声明落在预算内
GLB运行时真正加载的东西单文件自包含，米制，底面落 Y=0，正面朝 +Z，平直着色
验收图证明生成结果没有背离设定表与设定表同机位的五视图加三视角，白底，无后期

为什么不能只要一张图

现有提示词走的是三分之四视角、暖光、单主体。这套写法是为了"好看"，重建出来会踩三个坑，而且三个坑在本项目里都会立刻穿帮。

坑后果本项目的暴露点
只给一个视角背面、屋顶由模型自由发挥，往往糊成一块或长成圆顶客户端四向镜头加自由旋转，四个面天天被看到
透视 + 戏剧光重建端把阴影当成形体，屋檐与墙面的分界被焊死法线重建后出现斜面台阶，平直着色下极其明显
无尺度参照所有资产被归一化到同一尺寸弓箭塔和粮仓一样高，占地预览与寻路半径全错

低模平涂风格反而是图生三维的甜点区，面少、色块平、结构简单，这类算法最擅长。问题不在"能不能生"，在"有没有把约束交给它"。

为什么不能只要 GLB

三维服务默认导出的是"展示用模型"，不是"入库模型"。默认输出会同时违反下面几条硬约束，而这些约束全部来自现有代码，不是偏好。

格式

项要求原因
容器glTF 2.0 二进制 .glb 单文件资产包只收 GLB，其它格式要走一次转换
纹理内嵌 bufferView，不引用外部 .png 或 .bin加载用 parseAsync(buffer, "")，外部相对路径解析失败
压缩禁 Draco、meshopt、KTX2客户端只有裸 GLTFLoader，没有挂解码器
体积单模型不超过 32 MB，整包不超过 64 MB资产包校验硬上限
附加物无动画、无相机、无灯光、无地面底座建筑是静态实例，底座会压坏地形贴合

几何

项要求现状参考
单位米制，Y 轴向上全项目统一
原点底面中心，落地 Y=0资产直接落在放置点
朝向正面 +Z，门与入口在 +Z 面程序化建筑的门在 depth / 2
建筑体量占地 1.7–2.3 m，高 3.8–4.7 m，塔 5.8 m现有八类建筑
三角面建筑上限 6000，目标 2000–3500现状 533–1614
着色平直着色，法线按面，关闭平滑与自动平滑平涂风格的前提

朝向这一条仓库里有两份说法。docs/Marchlands-资产包.md 写"默认面向 -Z"，而执行门朝向的代码与提示词文档都是 +Z。以 +Z 为准，那份文档该改。

材质

项要求
贴图512 到 1024 见方，仅 albedo，PNG 或 JPEG
禁烘焙无光影、无 AO、无高光、无法线贴图、无金属度贴图
队伍色角色材质名 team_roof、team_edge、team_cloth
队伍色底这三类面的 albedo 必须是纯白或纯灰
固定色灰泥 #D9CAAB，石 #8D8676，木 #4A3626，草秸 #C6A55E，草 #58743C

队伍色是拿 material.color 直接覆盖再与贴图相乘。队伍色面只要带一点烘焙阴影，换绿换红就会发脏，这是最常见的入库失败原因。

可直接粘贴的指令块

你是技术美术，不是概念插画师。任务是为 Marchlands 交付可直接入库的低模建筑资产。

项目约束
- Three.js 运行时，米制，Y 轴向上，模型正面朝 +Z，原点在底面中心，落地 Y = 0
- 建筑占地 1.7 到 2.3 米，高 3.8 到 4.7 米，塔楼 5.8 米
- 三角面上限 6000，目标 2000 到 3500
- 贴图只允许 albedo，1024 见方，无烘焙光影，无 AO，无高光，无法线贴图
- 平直着色，法线按面，不启用平滑
- 单一自包含 GLB，纹理内嵌，不引用外部文件
- 禁止 Draco、meshopt、KTX2、动画、相机、灯光、地面底座、文字

交付四件
1 正交设定表
   五视图：正面、背面、左侧、右侧、顶视
   正交投影，无透视，无景深，无投影，均匀平光，中性灰背景
   五视图同缩放同基线，画布底部标注总高与占地米数
   顶视图给出完整屋顶轮廓与挑檐进深
2 规格单 JSON，字段按给定模板
3 模型 GLB
4 验收图：模型五视图加三视角，机位与设定表一致，白底

风格
低模、平涂、面切分明、体块手作感，配色只用灰泥、石、胡桃木、草秸、草绿
暖光只出现在验收图，不出现在贴图里

禁止
透视夸张、英雄机位、戏剧光、地面与天空、多物体、写实材质、金属度、文字水印、任何后期

规格单模板

{
  "id": "com.marchlands:barracks-L2",
  "kind": "building",
  "label": "步兵营 · 驻所",
  "family": "barracks",
  "tier": 2,
  "file": "models/barracks-L2.glb",
  "footprint": 2.0,
  "height": 4.4,
  "triangles": 3200,
  "texture": { "size": 1024, "maps": ["albedo"] },
  "materials": {
    "team_roof": "#FFFFFF",
    "team_cloth": "#FFFFFF",
    "plaster": "#D9CAAB",
    "stone": "#8D8676",
    "timber": "#4A3626",
    "straw": "#C6A55E"
  },
  "units": "meter",
  "up": "+Y",
  "front": "+Z"
}

前九个字段可以直接映射到 pack.json 的资产条目，id 换成包命名空间即可。triangles 与 texture 不进入格式，但它们是验收时的比对基准。

按家族生成，不要逐件生成

八类建筑每类三级，共二十四件。逐件生成会得到二十四套互不相干的语言，拼在同一张图上立刻露馅。正确做法是一次生成一族，让三级同框。

同一座步兵营的三个等级，左到右并排，同一张正交正面图。
三级共用同一墙体材质、同一门窗母题、同一屋面瓦型、同一配色。
差异只体现在高度、体块数量、屋顶形态、道具密度四项里，至少三项不同。
L1 单坡木棚加栅栏，L2 主屋加侧翼加望楼，L3 石基双层加角楼。
三件轮廓高度递增但风格同源，可并排展示，无文字标注。

验收标准本来就是"四项里至少三项不同"，把这句话原样交给模型，比事后返工便宜得多。同一族的贴图共用一张，也省掉一半图集。

入库前的六项校验

检查失败意味着
包围盒最低点 Y 约为 0，水平中心约为 0悬空或陷地，放置点偏移
包围盒高度与规格单相差不超过 5%尺度漂移，塔与粮仓同高
三角面数在预算内移动端掉帧，实例化后放大
材质名包含声明的队伍色角色换阵营不生效，绿方红方同色
队伍色角色贴图接近纯白染色发脏，这是最常见的返工项
extensionsRequired 为空或只含已知安全项运行时报解析失败，直接白模

这六项不需要打开 Blender，读 GLB 的 JSON chunk 与 POSITION 的 min/max 就能算。仓库里加一个 tools/asset-check 大约百来行，可以接进 pnpm 脚本，也可以直接跑在生成回来的批次上。

现实的取舍

  • 图生三维给的是不可编辑的三角面，没有干净的四边面拓扑。做静态据点建筑、装饰、地形块够用，做需要 LOD、破坏、骨骼动画的东西不够。
  • 建筑是本项目最合适的切入点。它们静态、体量固定、永远四向可见、从不形变，正好避开图生三维的全部短板。
  • 兵种不建议走这条路。四头身角色要骨骼、要四个动作剪辑、要轮廓在 0.9 米高度上可读，重拓扑的成本高于直接买 CC0 套件。
  • 生成回来的模型即便过了六项校验，法线朝向与三角面绕序仍可能反。渲染时若出现黑面，先在三维端统一重算法线再入库。
