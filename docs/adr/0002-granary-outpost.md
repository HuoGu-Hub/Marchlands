# ADR 0002：粮仓与临时驻兵点

日期：2026-11-02
状态：已采纳（用户直接指定）
关联：[开发指南](../Marchlands-开发指南.md)

## 背景

首版只做城镇、派兵、战斗与升级。用户要求在 M1 中加入两套新机制：

1. 粮仓不产兵，可屯兵，并为己方部队提供行军速度与战斗力增幅。
2. 临时驻兵点可路边设伏，驻扎一段时间后开始掉兵；守军可选避战或迎战。

两套机制都必须进入确定性模拟核心，不能只做表现层。

## 决策

### 据点

- 复用 `CityState` 作为统一据点状态，新增 `kind`：
  - `town`：原有城镇，产兵、产金币、可升级，计入胜负。
  - `granary`：粮仓，不产兵、不产金币、不可升级，可屯兵。
  - `outpost`：临时驻兵点，不产兵、不产金币、不可升级，可屯兵，可设伏。
- 粮仓与驻兵点在地图图论上都是叶子节点：只有一条支路连接公路节点。它们不在城镇之间的最短路上，不是必须攻占点位。
- 临时驻兵点额外带 `watch`：监视一条真实公路边；`stance` 为 `evade`（避战）或 `engage`（迎战）。
- 地图校验要求：
  - 粮仓/驻兵点度数必须为 1。
  - 驻兵点的 `watch` 必须是地图中真实存在的边，且支路端点必须是该边的一个端点。
  - 只有驻兵点可以带 `watch` 与 `stance`。

### 粮仓

- 容量 50，防御 1.30，不增长、不产金币。
- 己方拥有至少一座粮仓时，该玩家获得：
  - 行军速度 +20%。
  - 部队战斗力 +20%（攻防都按 1.2 计）。
- 多座粮仓不叠加；只看“是否拥有至少一座”。
- 部队出发时把速度与战斗力增幅写入 `SquadState`，飞行途中粮仓易手不改变该队伍；防守方按战斗发生时的粮仓归属计算。
- 粮仓空置也提供增幅；“拥有”指归属，不要求驻军。
- 攻占粮仓后，守军按普通战斗结算，剩余兵力成为新驻军。

### 临时驻兵点

- 容量 50，防御 0.80。
- 驻扎宽限期 600 tick（30 秒），之后每 200 tick（10 秒）损失 2 兵。
- 友军增援到达会重置宽限期；兵力归零时据点变为中立、状态回到避战。
- 驻兵点不计入城镇数、人口对比或胜负条件。玩家失去全部城镇时，即使还持有粮仓/驻兵点也被淘汰。
- 默认状态避战；攻占后也重置为避战，由新主人决定是否迎战。

### 路边拦截

- 迎战状态下，敌方队伍经过 `watch` 边时会被拦截。
- 拦截点在边的中点；拦截 tick 用队伍出发时的速度换算，保持确定性。
- 拦截只与驻兵点守军打一场遭遇战，路过队伍不会占领驻兵点：
  - 路过方战斗力大于守军防御：守军全灭，驻兵点中立，路过方按比例损失后继续行军。
  - 否则：路过方全灭，守军按剩余防御值保留。
- 避战只影响“路过拦截”；敌方直接以驻兵点为目标时，无论状态都必须交战，胜方占领据点。

### 战斗公式

```text
攻击力 A = floor(队伍兵力 × 攻击方增幅 / 1000)
防御力 D = floor(守军人口 × 据点防御千分比 × 防守方增幅 / 1000000)

A > D:
  守军全灭
  进攻方损失 = min(兵力, floor(D × 1000 / 攻击方增幅))
  进攻方剩余 = 兵力 - 损失；占领后不超过据点容量
否则:
  进攻方全灭
  守军剩余 = min(原人口, max(0, D - A))
```

无粮仓时增幅为 1000，公式退化为原版规则。

### 指令与事件

- 新增指令 `setStance { city, stance }`；只能对己方驻兵点使用。
- 新增事件：
  - `squadIntercepted`：拦截双方损失、是否全灭。
  - `outpostDecayed`：掉兵数量与剩余人口。
  - `stanceChanged`：驻兵点状态切换。
- 既有 `squadSpawned`、`squadArrived`、`combatResolved`、`cityCaptured` 继续覆盖新据点。

### tick 顺序

1. 指令：派兵、升级、切换驻守状态。
2. 城镇人口与金币增长。
3. 队伍推进：先结算迎战拦截，再结算到达。
4. 驻兵点掉兵。
5. 胜负检查。
6. tick +1。

先结算拦截再结算到达，使迎战驻兵点可以在敌军抵达相邻城镇前消耗它；增援与占领在本 tick 先发生，再进入掉兵，因此增援可以重置宽限期。

### 首图布置

- `g1`、`g2`：两座中立粮仓，分别支路连接 `c4`、`c5`。
- `o1`：中立驻兵点，支路连接 `c4`，监视公路 `c4-c5`。
- `o2`：中立驻兵点，支路连接 `c7`，监视公路 `c6-c7`。
- 城镇、拓扑、坐标与原有胜负条件不变。

## 后果

- `CityState` 从“城镇”扩展为“据点”，渲染层与 HUD 需要按 `kind` 区分模型和文案。
- 胜负统计只认 `kind === "town"`；任何统计“城市数”的界面都必须过滤。
- 客户端选中驻兵点后可用 `R` 切换迎战/避战；正式按钮留给 UI 层。
- AI 会优先拿第一座粮仓，并把己方驻兵点切到迎战；不主动进攻驻兵点。
- 所有数值集中在 `packages/content/rules/1.json`，后续调平衡不需要改模拟代码。

## 不变

- 20 Hz 固定步长、整数人口/金币、种子确定性、状态哈希。
- 原有城镇升级、金币累计与 `capture_all`/`eliminated`/`time_limit` 结算。
- 模拟核心不引入 DOM、Node API、随机数或时间。
