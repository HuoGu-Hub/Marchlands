# ADR 0003：行军改道与兵团粮草

日期：2026-11-02
状态：已采纳（用户直接指定）
关联：[开发指南](../Marchlands-开发指南.md)、[ADR 0002](0002-granary-outpost.md)

## 背景

原实现中，派兵时一次性算好最短路径，队伍沿路径走到目标，中途不能改变。用户要求把“行军”做成可操作的过程：

1. 点击路上的兵团，高亮当前路线，低亮所有仍可抵达目的地的其他路线。
2. 在到达下一个岔路口前，点击低亮路线即可改道；也可以直接点击据点更改目的地。
3. 每个兵团出发时携带粮草，安全行军一段时间后开始按频率掉兵，避免无限绕路。

## 决策

### 队伍路径状态

- `SquadState` 不再只保存一条静态 `path`，还保存：
  - `pathIndex`：当前正在走的边在 path 中的下标。
  - `legStartTick` / `legEndTick`：当前边开始与到达下一个节点的 tick。
  - `arrivalTick`：当前计划抵达最终目标的 tick。
- 改道在**下一个节点**生效，不允许在一条边的中间掉头。这样位置、到达时间、迎战拦截都保持整数 tick 与确定性。
- 队伍抵达中间节点时只推进 `pathIndex`，不改归属；抵达最终节点才结算战斗/增援。
- 同 tick 多支队伍仍按 squadId 升序结算。

### 改道指令

~~~ts
{ type: "retarget"; squad: string; to: CityId; via?: CityId }
~~~

- `to`：新的最终目的地。
- `via`：下一个节点之后要走的第一条边；省略时从下一个节点走最短路径。
- `via` 必须是下一个节点的邻居，且从 `via` 能到达 `to`；否则拒绝。
- 指令可以在任意时刻发出，但只在到达下一个节点时改变后续路径；当前边不变。
- 改道不返还、不重置粮草；已结算过的迎战拦截不重复结算。
- 目的地就是下一个节点时，队伍到达该节点即结算，不再前进。

### 路线显示

- 新增纯函数 `routeOptions(graph, squad)`：
  - 从当前边的下一个节点出发。
  - 对每个邻居给出一条可抵达目的地的简单路线。
  - 过滤已经走过的节点，避免展示无意义的回头路。
  - 当前计划标记为 `current`。
- 客户端只用这个函数生成显示数据，不在 UI 里重复寻路逻辑。
- 当前路线亮色实线；其他路线暗色虚线。点击暗色路线发送 `retarget` 的 `via`；点击据点发送新的 `to`。
- 路线叠加层是独立的 2D canvas，不改 3D 场景。投影通过 `BattleScene.projectCity` 采样若干据点，拟合正交相机的平面仿射变换；竖轴偏移由仿射矩阵的奇异值差得到。这样旋转、缩放后仍能对齐，且不依赖场景私有相机。

### 粮草

- 新增 `rules.supply`：
  - `carryTicks`：出发后可安全行军的 tick 数。
  - `starveIntervalTicks`：断粮后掉兵间隔。
  - `starveLoss`：每次掉兵数。
- 默认值：600 / 200 / 1，即 30 秒安全期，之后每 10 秒掉 1 兵。
- 出发当 tick 不消耗粮草；之后每 tick 消耗 1。`supplyLeft` 归零后开始掉兵。
- 改道、战斗损失、迎战拦截都不重置粮草。
- 粮草耗尽时发 `squadStarved` 事件；兵力归零则队伍消失，不再参与到达结算。
- 首版不提供粮仓补给、粮草购买或队伍合并。

### tick 顺序

1. 指令：派兵、升级、驻守状态、改道。
2. 城镇人口与金币。
3. 队伍推进：先迎战拦截，再推进中间节点与最终到达。
4. 粮草消耗与断粮掉兵。
5. 驻兵点掉兵。
6. 胜负与时间上限。

## 后果

- `SquadState` 的哈希字段增加；旧回放不兼容，按机制升级处理。
- 客户端新增路线叠加层与兵团信息卡；选中兵团时隐藏城镇面板。
- 点击兵团优先于点击城镇，避免队伍经过城镇时无法选中；代价是城镇附近有队伍时可能需要错开点击。
- 暗色路线只展示“下一个节点的一跳 + 最短后续”，不是指数级枚举所有简单路径；后续岔路会在抵达后继续展示。
- AI 暂不使用改道；粮草只作为长距离/反复绕路的约束。
- 所有数值在 rules/1.json 中可调。

## 不变

- 20 Hz 固定步长、种子确定性、状态哈希。
- 派兵仍从己方据点扣兵，到达才结算战斗。
- 粮仓增幅、驻兵点迎战拦截与胜负规则不变。
- 模拟核心不引入 DOM、Node API、随机数或时间。
