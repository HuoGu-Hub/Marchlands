## 0. 这份文档的用途

这是后续实现的契约。实现过程中如果发现必须偏离，先改这份文档，再改代码。

当前基线：

- `MapDocument` 为 schema 2，包含据点、道路、视觉层、单位外观。
- `MapDef` 为 schema 1，只包含据点图数据。
- `packages/sim/src/path.ts` 的 `MapGraph` 使用 Dijkstra。
- 地图边已经有 `grade`，代价为 `length × (1 + grade × 3)`。
- 地形高度由 `packages/map-authoring/src/height.ts` 运行时生成，客户端与编译器共用。
- 客户端道路、城市、装饰、兵团已经贴地；编辑器点击使用地形射线。
- 建筑、城堡、城镇已经走 GLB；单位支持 GLB 动画与程序化回退。
- 这些都保留，不在本次改造中推翻。

## 1. 目标与非目标

### 1.1 目标

1. 地图可以自由制作：高度、坡道、悬崖、水面、阻挡、道路都由地图数据决定。
2. 兵团在地图上连续移动，不再只能沿据点边移动。
3. 使用确定性网格 A* 寻路。
4. 地形高度参与碰撞：坡度、台阶、悬崖、水面、建筑占地。
5. 道路从“唯一通路”降级为“更快的通行层”。
6. 保留旧据点图地图可运行，新增网格地图模式。
7. 为视野预留数据与接口，但本阶段不实现战争迷雾。

### 1.2 非目标

- 不做 navmesh。
- 不做战争迷雾、视野锥、侦察。
- 不做动态地形破坏。
- 不做多人网络同步。
- 不要求旧官方图立刻迁移到网格。
- 不重做美术资产。

## 2. 核心决策

| 项目 | 决策 |
|---|---|
| 地图表示 | 高度场 + 可通行网格 |
| 网格尺寸 | 1 米/格 |
| 方向 | 8 方向，禁止贴角穿越 |
| 寻路 | 确定性 A* |
| 高度单位 | 整数厘米 |
| 坐标单位 | 运行时统一为整数厘米 |
| 地图文档坐标 | 继续使用分米，编译时转厘米 |
| 道路 | 速度/代价修饰层，不是拓扑约束 |
| 据点 | 战略对象，有 footprint 和占领半径 |
| 旧地图 | `navigation: "graph"`，继续走 MapGraph |
| 新地图 | `navigation: "grid"`，走 NavGrid |
| 视野 | 只加 `vision.enabled` 字段，默认 false |

### 2.1 为什么不是 navmesh

- 网格更适合玩家在编辑器里刷地形、看可走范围。
- 网格的确定性、调试和回放更容易。
- 1 米网格的数据量和性能完全够用。
- navmesh 更适合大量单位平滑移动，但编辑器和动态更新复杂，不适合当前阶段。

### 2.2 为什么保留旧图模式

一次性替换会影响：

- 三张官方地图。
- AI 选路。
- 粮草、改道、驻兵点监视。
- 全部回放测试。

双模式可以让新功能先跑通，再逐张迁移。

## 3. 数据模型

### 3.1 MapDocument v3

新增 `navigation` 和 `grid`：

~~~text
MapDocument
  schema: 3
  navigation: "graph" | "grid"
  grid:
    cellSizeDm: number        // 10 = 1 米
    width: number             // 格数
    height: number            // 格数
    heightCm: number[]        // 每格高度，长度 width × height
    surface: number[]         // 地表枚举
    blocked: string           // Base64 位图，1 = 阻挡
    walkableOverride: string  // Base64 位图，1 = 强制可走
  roads:
    from/to 保留              // 旧图兼容
    path?: [number, number][] // 网格图的道路样条，分米
    widthDm?: number
  cities:
    pos 保留
    footprintDm?: number      // 城镇占地直径
    captureRadiusDm?: number
  props:
    blocker?: boolean         // 是否参与导航阻挡
    footprintDm?: number
  vision:
    enabled: boolean          // 本阶段固定 false
~~~

### 3.2 高度

- 每格一个高度，整数厘米。
- 范围 `-32768..32767`，足够。
- 不再运行时按 seed 生成。
- 编辑器可以先用噪声生成初始高度，但保存时必须烘焙进 `heightCm[]`。

### 3.3 地表枚举

~~~text
0 草地
1 泥土
2 岩石
3 道路
4 浅水
5 深水
6 雪地
7 沙地
8 桥面
9 楼梯
~~~

地表影响：

- 颜色。
- 移动速度。
- 是否默认可走。
- 未来视野/隐蔽。

### 3.4 序列化

- 编辑器保存：JSON 数组，便于调试和手工修改。
- 运行时：编译为 Base64 的 Int16/Uint8/位图，减少体积。
- 地图文件必须带 `mapHash`，回放校验用。
- 旧 schema 2 地图加载时升级：
  - `navigation = "graph"`。
  - 不生成网格，保持旧行为。
  - 用户点“转换为网格地图”时再生成默认平面网格、把道路画成道路层、把据点写成 footprint。

### 3.5 MapDef v2

~~~text
MapDef
  schema: 2
  navigation: "graph" | "grid"
  grid?: {
    cellSizeCm: 100
    width, height
    heightCm: string       // Base64 Int16
    surface: string        // Base64 Uint8
    blocked: string        // Base64 位图
    walkableOverride: string
  }
  cities[]                 // 增加 footprintCm, captureRadiusCm
  edges[]                  // 旧图模式保留；网格模式可为空
~~~

现有 `schema: 1` 地图继续可读，按 graph 模式处理。

## 4. 运行时坐标与确定性

### 4.1 坐标

- 运行时统一使用**整数厘米**。
- 旧地图的分米坐标乘 10。
- 网格格子中心：`(x * cellSizeCm + cellSizeCm / 2)`。
- 所有位置、速度、半径都用整数厘米。
- 距离用整数平方根，避免浮点误差。

### 4.2 代价

整数代价示例：

~~~text
直走基础代价 = 1000
斜走基础代价 = 1414
道路倍率 = 700 / 1000
上坡倍率 = 1000 + slope * 4000
下坡倍率 = 1000 - slope * 1000
草地倍率 = 1000
泥地倍率 = 1300
浅水倍率 = 1600
深水 = 不可走
~~~

最终代价用整数乘除，结果取整。

### 4.3 A* 确定性

- 使用固定容量二叉堆。
- 相同 `f` 值按格子索引升序。
- 不依赖对象遍历顺序。
- 路径结果缓存键包含 `blockedVersion`。
- 回放只记录指令、地图哈希、种子。

## 5. 碰撞规则

### 5.1 静态阻挡

不可走：

- 深水。
- 建筑 footprint。
- 标记为 blocker 的岩石/树木/装饰。
- 编辑器手动画的禁行区。
- 坡度超过上限。
- 台阶超过上限。

可走覆盖优先于阻挡，用于：

- 桥。
- 浅滩。
- 楼梯。
- 城门。

### 5.2 坡度

默认参数，可在地图 ruleset 覆盖：

~~~text
最大可走坡度：700‰，约 35°
判定：相邻格的 |高差| / 水平距离，斜走用格宽 × 1.414
~~~

没有独立的“最大单步台阶”规则。旧字段 `maxStepCm` 已删除；地图级 `climbCm` 表示一格最多爬多少厘米，除以格宽就是坡度上限。

坡道不是特殊对象，而是连续高度变化：

- 相邻格坡度不超过兵种上限即可通行。
- 编辑器“坡道刷”自动生成渐变。
- 超过阈值的陡坎自动不可走。
- 显示面可以平滑、倒圆角、做噪声扰动，不影响这条判定。

### 5.3 单位体积

默认：

~~~text
步兵半径：40 cm
弓兵半径：40 cm
骑兵半径：80 cm
器械：120 cm
~~~

A* 使用**膨胀阻挡图**：

- 先按单位半径膨胀阻挡格。
- 再在膨胀图上寻路。
- 不同半径预计算不同 clearance 层，或按半径动态计算。

### 5.4 动态单位

- 单位之间不做严格 A* 阻挡。
- 使用空间哈希做局部避让。
- 必要时给拥挤格加软代价。
- 避免单位互相卡死。

## 6. 移动与玩法

### 6.1 兵团状态

~~~text
SquadState
  xCm, zCm
  path: waypoint[]
  pathIndex
  speedCmPerTick
  legStartTick, legEndTick
  arrivalTick
~~~

### 6.2 移动

- 每个 tick 沿路径前进固定厘米。
- 到达 waypoint 后切换下一段。
- 高度按当前位置采样。
- 上坡/下坡速度倍率在进入格子时计算。
- 路径被阻挡更新时重新 A*。

### 6.3 占领与战斗

- 城镇有 `captureRadiusCm`。
- 兵团进入范围开始占领。
- 战斗按单位距离触发，不再按边相遇。
- 粮草按实际路径长度消耗。
- 驻兵点监视改为区域/道路段触发。

### 6.4 通路与阻挡

- `transit: friendly` 改为敌方控制区/占领 footprint 的软阻挡。
- 友军格子可通行。
- 敌军城镇 footprint 高代价或不可通行。
- 具体规则在实现前补一张表。

## 12. 风险

1. **范围过大**：必须按阶段提交，每阶段可运行。
2. **AI 退化**：网格 A* 的 AI 目标选择需要重写，先做简单目标再优化。
3. **编辑器复杂度**：高度刷和导航预览是最大工作量。
4. **回放漂移**：整数坐标、整数代价、稳定排序必须从第一阶段贯彻。
5. **旧机制语义**：驻兵点、友方通行、改道需要重新定义。
6. **性能**：大量单位同时寻路，需要缓存/flow field。
7. **数据体积**：大地图高度场需要压缩。

## 16. 完成定义

本计划完成 = 以下全部成立：

1. 编辑器可以刷高度、坡道、悬崖、水面、阻挡。
2. 玩家可以制作一张非据点图结构的自由地图。
3. 兵团在网格上连续移动并绕开障碍。
4. 坡道可走，悬崖不可走。
5. 城镇可占领、战斗、粮草、AI 正常工作。
