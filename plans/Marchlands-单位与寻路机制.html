单位与寻路机制

规格版本 2026-11-04 · 以此文为准

1. 网格与坐标

一二
三四五
六
七八九

空白格不可通行；有字格可通行。精兵从一出发，到八的路线为 一 → 四 → 六 → 八，不是一二六八九。六是单格瓶颈，两侧没有可绕行格。

2. 单位档案

字段含义
surface可通行地表集合，例如陆路、浅水、水路。
maxStepCm相邻两格允许的最大高度差，厘米。
footprint占地格数。普通兵/精兵 1×1，盾兵 1×2。
turnFootprint转弯所需空地。盾兵为 2×2。

高度差是逐边判定，不是整条路线累计。例：精兵 maxStepCm = 10000，普通兵 500；同一条边高差 5000cm 时精兵能走、普通兵不能。

3. 盾兵 1×2 的格位

盾兵的格位不是单格中心，而是 (x, z, orientation) 两个相邻格。起始占 (1,2) 时，只能整体平移到 (4,5)，不能从六这种单格通道通过。

横放： (x,z) + (x+1,z)
竖放： (x,z) + (x,z+1)
平移：保持朝向，两格同时可走且高度差满足
转弯：目标处的 2×2 区域内四格全部可走，才允许换朝向
对角：不改变占地合法性，但路径代价按两格移动中的最大值计算

盾兵不能只移动一半格位；任何移动、转弯、贴墙都按完整占地检查。

4. 建筑与兵种

建筑产出兵种说明
兵营步兵固定绑定。
马厩骑兵固定绑定。
盾兵营盾兵固定绑定。
弓兵营弓兵固定绑定。
弓箭塔无只防御，不产兵。

所有可产兵建筑能且只能产一种兵。建筑外观模型在导入资产时绑定建筑类型，运行时不按模型哈希临时决定兵种。

5. 建筑通行状态

归属状态来源局内是否可改
中立创建地图时的默认值玩家不可改
已被占领占领方设置，默认继承被占领前的状态或占领方默认占领方可改

状态只有两种：

  • 放行：非己方兵团无需战斗直接通过；终点是建筑本身时仍进入占领结算。
  • 拦截：非己方兵团必须战斗并攻占后才能通过。

己方建筑永远放行。非己方建筑按通过瞬间的状态判定，而不是按出发时的快照。

6. 逐兵通过

兵团进入建筑格时：
  for each 尚未通过的士兵:
    读取建筑当前状态
    己方 / 放行 -> 标记已通过
    拦截 -> 该士兵与守军结算
  已通过的部分继续前往目的地，不回头
  未通过且战斗失败的部分留在建筑前，按战斗结果处理
  攻占成功后，剩余士兵继续通过

状态在兵团通过途中从放行改为拦截时，只影响尚未通过的士兵；已通过的士兵不会被拉回。

7. 寻路顺序

  1. 起点与终点所在格可通行。
  2. 过滤当前兵种不能走的地表。
  3. 逐边检查高度差 abs(h1 - h2) <= maxStepCm。
  4. 按 1×1 或 1×2 占地检查通道宽度；转弯检查 2×2。
  5. 检查路线上建筑在规划时的通行状态，只作为路线候选；实际通过时再逐兵复核。

建筑状态会变化，所以长距离路线必须有“进入建筑前重新校验”的事件，不能只在出发时算一次。

8. 代码改动范围

层改动
地图数据新增建筑类型、unitKind、中立默认通行状态；外观资产绑定建筑类型。
模拟兵团增加 unitKind；建筑增加运行期通行状态与切换命令；通过建筑时逐兵结算。
寻路按兵种档案生成可走掩码、高度规则、占地与转弯规则；建筑格动态成本/阻挡。
界面建筑检查器设置默认通行状态、占领后切换；出兵建筑显示唯一兵种。
资产导入建筑模型时选择建筑类型；类型决定可产出兵种。

9. 实施阶段

  1. 数据模型：兵种档案、建筑类型、建筑默认状态、兵团兵种。
  2. 网格寻路：1×1 兵种地表/高差/宽度；1×2 盾兵平移与 2×2 转弯；用 1–9 网格做固定测试。
  3. 建筑通过：逐兵状态、拆分、战斗、攻占后继续。
  4. 局内切换：占领方切换拦截/放行，已通过士兵不回退。
  5. 编辑器与资产：建筑类型绑定、默认状态、出兵展示。

10. 待确认

城镇是否产兵？ 当前游戏只有城镇、粮仓、驻兵点。上表没有“城镇”这一行；如果城镇也产兵，需要指定它固定产哪一种；如果不产兵，现有从城镇出兵的操作要迁移到兵营等建筑。

粮仓、驻兵点归入哪类建筑？ 它们当前有守军和功能，但不一定属于“可产兵建筑”。

盾兵初始朝向、建筑占格数、建筑是否阻挡整格会直接影响网格寻路数据结构，需要在实现前固定。
